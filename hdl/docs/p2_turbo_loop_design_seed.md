# P2 — Iterative Turbo-Decoder Loop: design seed

Status: **planning seed, not yet an OpenSpec change.** P2 becomes a formal
change (`add-fpga-turbo-decoder-loop`) only after P1
(`add-fpga-constituent-decoder`) is implemented and verified — the loop reuses
the P1 core unmodified (standalone-before-integration discipline). This
document captures the data flow worked out from `turbo_decoder.m` while it is
fresh, so P2's proposal/design start from a known-good shape.

Scope of P2: fixed `max_iterations`, **no** CRC early-termination, **no**
filler/`NaN`. Those are P3.

---

## 1. Data-flow algebra (distilled from `turbo_decoder.m`)

```
 once, from d_a (3×(K+4)):                      [no filler in P2]
   z_a[0..K-1]       = d_a(2, 0..K-1)           upper parity a-priori
   z'_a[0..K-1]      = d_a(3, 0..K-1)           lower parity a-priori
   z_a[K..K+2], x_a[K..K+2]                     upper termination (de-mux)
   z'_a[K..K+2], x'_a[K..K+2]                   lower termination (de-mux)
   ch_sys[0..K-1]    = d_a(1, 0..K-1)           channel systematic LLR
   c_a[0..K-1]       = 0                         interleaved extrinsic (state)

 per UPPER half:
   x_a[0..K-1] = c_a + ch_sys
   x_e         = constituent_decoder(x_a, z_a)        ← P1 core, UNMODIFIED
   c_e[0..K-1] = x_e[0..K-1] + ch_sys                 (x_e[K..K+2] discarded)

 per LOWER half (skipped on final half if 2·max_iter is odd):
   x'_a[0..K-1] = c_e[ pi[k] ]                         interleave (read c_e @ pi)
   x'_e         = constituent_decoder(x'_a, z'_a)      ← P1 core, UNMODIFIED
   c_a[ pi[k] ] = x'_e[0..K-1]                         deinterleave (scatter c_a)

 after all halves:
   c[k] = (c_a[k] + c_e[k]) < 0   for k=0..K-1         K hard-decision bits out
```

`x_a`/`x'_a` termination triplets and `z_a`/`z'_a` are **constant across
iterations** — only the systematic a-priori body changes. The constituent core
never sees "channel vs extrinsic"; P2 is the surrounding add / interleave /
hard-decision / iteration FSM. This is exactly the P1/P2 cut the roadmap drew
— **confirmed by the code**.

## 2. Half-iteration reframing (cleaner than MATLAB ceil/floor)

`max_iterations` is a multiple of 0.5. Let `H = round(2·max_iterations)` =
number of half-iterations. Iterate `h = 0..H-1`:

```
   h even → UPPER half      h odd → LOWER half
```

This makes the 0.5 granularity and the "skip final lower half" case fall out
naturally (just stop at `H`), avoiding the float ceil/floor logic in HW.

## 3. Reuse (all already verified — the standalone-before-integration payoff)

| Reused core | Role in P2 | Status |
|---|---|---|
| `constituent_decoder` (P1) | one instance, called 2×/iteration (upper, then lower) with muxed `(x_a,z_a)` / `(x'_a,z'_a)` | P1 deliverable |
| `qpp_interleaver` | streams `pi[k]` for the interleave read & deinterleave scatter | ✅ verified |
| `qpp_rom` | `K → (d0,step)` for the QPP — same instantiation pattern as `turbo_encode_top` | ✅ verified |

One constituent instance (sequential upper→lower) for sim-first v1; a second
instance for pipelining is a later throughput option, not v1.

## 4. Memory map (K ≤ 6144; sim-first, async-read like prior tops)

```
 persistent (set once):  z_a[K+3], z'_a[K+3], ch_sys[K]            (LLR words)
 state (per half):        c_a[K], c_e[K]                            (LLR words)
 termination consts:      x_a[3], x'_a[3]                            (tiny)
 pi:                      regenerated by qpp_interleaver per use     (no RAM)
 + inside the reused core: α RAM 8×(K+3)
 ──────────────────────────────────────────────────────────────────────────
 ≈ 5·K LLR words + α RAM    → modest, GHDL-OK (cf. circular_buffer w[18528])
```

`pi` is needed twice per lower half (interleave read, deinterleave scatter).
**Decision for v1:** regenerate `pi` from `qpp_interleaver` each time (no
K-entry RAM, +K cycles) rather than store it — simpler, consistent with
sim-first. Storing `pi` is a throughput option later.

## 5. FSM sketch

```
 S_IDLE ─in_start─► S_LOAD_D ──► S_HALF_DISPATCH ──┐
                    (de-mux d_a,     ▲             │ h<H ?
                     c_a=0, h=0)     │             ▼
                                     │      h even │ h odd
                                     │   ┌─────────┴─────────┐
                                     │   ▼                   ▼
                                     │ S_UP_BUILD         S_LO_ILV
                                     │ (x_a=c_a+ch_sys)   (drive qpp; x'_a=c_e[pi])
                                     │   ▼                   ▼
                                     │ S_UP_DEC           S_LO_DEC
                                     │ (constituent core) (constituent core)
                                     │   ▼                   ▼
                                     │ S_UP_CE            S_LO_DILV
                                     │ (c_e=x_e+ch_sys)   (drive qpp; c_a[pi]=x'_e)
                                     │   └────── h++ ────────┘
                                     └────────────┘
                            (h==H) ──► S_FINAL ──► S_OUT ──► S_DONE
                                       (c=(c_a+c_e)<0)  (stream K bits)
```

`S_UP_DEC`/`S_LO_DEC` *are* the reused constituent core's run (≈ load + α +
β/extrinsic). The interleave/deinterleave states drive `qpp_interleaver` and
use its `pi[k]` to address `c_e` (async read) / scatter-write `c_a` — the same
"interleaver-address → buffer" pattern `rate_matching_top` already uses.

## 6. Cycle budget (pre-commit the large-K limit)

```
 constituent call ≈ 3·(K+3)         ; 2 calls per full iteration
 interleave + deinterleave ≈ 2·K    ; qpp regen
 per full iteration ≈ ~8·K ; H halves → ≈ ~4·H·K total
 K=6144, max_iter=8 (H=16) → ≈ 4·16·6144 ≈ 4·10^5 sim cycles/vector
```

→ P2 vector suite keeps **few** large-K cases (the `tx_chain_top` lesson,
already a locked roadmap constraint).

## 7. Resolves open thread: does P1 expose the 3 termination extrinsics?

**Yes — P1 keeps the `K+3` output.** It makes P1 a faithful standalone
`constituent_decoder` (clean equivalence vs `constituent_decoder.m`, which
returns `K+3`). P2 simply consumes `x_e[0..K-1]` and ignores the last 3. No
P1 interface change for P2's benefit.

## 8. Open questions for the P2 proposal (not P1)

- **Extrinsic-exchange fixed-point format.** `c_a`/`c_e` and the
  `+ch_sys` adds need a pinned Q-format (may differ from the core's internal
  α/β width). Inter-half **extrinsic scaling** (~0.75, a common Max-Log-MAP
  accuracy aid) is **M1**, not P2 — P2 just fixes *a* format and mirrors it
  exactly in the fixed-point turbo reference.
- **Fixed-point turbo reference** = P1's fixed-point constituent reference
  wrapped with this exact loop algebra; it is the P2 inner oracle. Outer =
  bounded BER vs float `turbo_decoder.m` (now meaningful — the loop exists).
- **One vs two constituent instances** — v1 one (sequential); two is a
  throughput maturation option.
